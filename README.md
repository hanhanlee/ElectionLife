# 選舉人生：市長篇

黑色幽默的市長模擬遊戲，純靜態網站。

選一個政黨、隨機抽出身背景，在虛構城市競選市長。兩個階段，各 12 回合：

- **第一階段：競選**——參選、政見、9 回合選戰、選前之夜 → 第一次投票，落選即結束。
- **第二階段：任期與連任**——8 回合任期、3 回合現任限定、連任選戰 → 第二次投票。現任市長背景的第二階段是不能再連任的第二任，最後是接班選舉。

## 結構

```
web/                          Next.js 16（output: export，無後端）
  src/game/types.ts           型別：數值、事件、選項、政黨、出身、來源
  src/game/model.ts           勝選模擬權重（會公開在結局頁）
  src/game/engine.ts          回合引擎（純函式、可用 seed 重現）
  src/game/endings.ts         結局判定與政治人格
  src/game/difficulty.ts      設定畫面的難度估算
  src/game/validate.ts        事件庫檢查
  src/content/events.json     事件庫
  src/content/parties.json    政黨：藍、綠、白、黃、其他小黨、無黨籍
  src/content/backgrounds.json 出身：現任市長、立委、議員、政務官、素人
  src/content/crises.json     突發事件：數值越過門檻時自動發生（不是選項）
  src/content/history.json    中選會彙總數字（由 scripts 產生，勿手改）
```

完整遊戲設定見 [docs/game-design.md](docs/game-design.md)（附錄由 `scripts/export_design_tables.py` 自動產生）。資料抓取腳本在 `scripts/`，原始與彙總資料在 `data/`，來源審閱見 [docs/data-sources-review.md](docs/data-sources-review.md)。

## 指令

在 `web/` 內：

- `npm run dev`：開發伺服器
- `npm test`：引擎與事件庫測試（含難度與史實校準）
- `npm run build`：輸出靜態網站到 `web/out/`

在專案根目錄：

- `python -I scripts/check_quotes.py`：確認事件引用的原文確實出現在本機保存的公報與政府文件中

## 事件撰寫規則

1. 場景、城市、政黨、人物一律虛構；不得出現真實姓名或可對號入座的細節。
2. 每個事件的 `source.prototype` 用中性語氣描述真實原型，不點名個人。
3. `status`：`placeholder`（純虛構草稿）→ `draft`（已附來源）→ `verified`（人工查核完成，必填 `reviewedBy`、`reviewedAt`）。
4. `draft` 以上必須附 `refs`，每筆都要有網址與**原文摘錄**；引用選舉公報時須通過 `check_quotes.py`。
5. 上線前 `validateEvents(events, { release: true })` 必須零錯誤。
6. 不預設任何行為必然帶來選票；調整 `effects` 後跑 `npm test` 確認難度仍在設計範圍內。平衡的目標是好玩、引人反思，史實數字只是參考。
7. 政黨的優勢與包袱只描述結構特性（組織、資源、形象），不評價政策立場；每個政黨都要同時有優勢與包袱。

## 設計目標

讓玩家反思：「這真的是我們想要候選人做的事嗎？如果候選人做了這個選擇，我們應該支持他嗎？」

- 結局的「換你當選民」會挑出玩家拿原則或公家資源換選票的選擇，以及為原則放棄選票的選擇，反問玩家身為選民會不會支持。
- 不同角色的勝率本來就不同：小黨、無黨籍挑戰者很難贏（約 10%），現任有優勢但不保證連任。

## 數值

| 數值 | 影響選票 | 解鎖／封鎖選項 | 太低（或太高）時 |
|---|---|---|---|
| 民調支持 | 主要來源，但越高越難再漲 | | 市民上街抗議 |
| 媒體聲量 | 投票當下的曝光，每回合退燒 | 高時出現「市長網紅化」 | 沒人記得你；太高則過度曝光 |
| 市庫財政 | 少量 | 花錢的選項需要它 | 財政警報 |
| 施政成果 | 連任時選民看的政績 | 高時解鎖展示成果的選項 | 「市長到底做了什麼？」 |
| 議會關係 | 少量 | 政策要過議會 | 總預算遭凍結 |
| 行政團隊 | 不直接 | 決定施政成果能實現多少 | 局處長集體請辭 |
| 政黨支持 | 組織動員；黨部撥款 | | 黨內逼宮、輔選放空 |
| 政商關係 | 不直接；政治獻金 | | 太高會爆出官商勾結疑雲 |
| 原則（隱藏） | 不直接 | 高時出現公民團體背書 | 檢調搜索市府、競選醜聞 |

## 競選經費

- 競選經費（萬元）和市庫財政是兩回事：前者是候選人自己的錢，後者是市府的錢。
- 每 3 回合入帳一次，分三項列出：
  - **黨部撥款**：政黨基數 ×（政黨支持 / 50），跟黨關係越好拿越多。
  - **政治獻金**：政商關係 × 10。
  - **小額捐款**：民調支持超過 35 的部分 × 12，素人與無黨籍的倍率較高。
- **個人貸款**：整局只能借一次，固定 3,000 萬，連本帶利 3,450 萬，從借款那回合起分期，每回合自動扣款，必須在該階段結束前還清。漏繳的期數之後會補扣，付不出來會上新聞，到期還不清就違約（民調 −10、原則 −5）。
- 競選期、選前之夜、任期尾聲與連任選戰，每回合有 300 萬的競選總部開銷。
- 造勢晚會、廣告、網路行銷都要花經費，錢不夠就鎖住；募款餐會、企業政治獻金可以籌錢，但會傷原則。
- 選前動員：投票前剩下的經費自動投入動員（最多 4,000 萬，每千萬加 0.15 logit），直接影響得票。
- 第一次投票與連任選舉使用不同的對手基準（`VOTE_BIAS`、`REELECTION_BIAS`），兩者都對所有角色一視同仁。錢要留到最後，但也不能一路省到什麼活動都不辦。
- 被檢調搜索要付律師費，醜聞會讓捐款人要求退款。
- 現任優勢：現任可以用市府預算辦「市政活動」（`perk` 選項），不花自己的競選經費。
- 每個事件都保證至少有一個不花錢、沒門檻、也不動用公家資源的選項，玩家不會卡住。

- 選項用 `requires` 設門檻：看得到但鎖住，並顯示需要的數值。用 `appearsIf` 設門檻：達到才會出現。
- 負面突發事件在數值持續低於門檻時，每 3 回合會再發生一次。重大事件會有持續幾回合的餘波（例如被搜索後連續 3 回合民調 −3），並設定旗標觸發後續事件（偵查中的市長、辯論會的第一題、財政緊縮方案、抗議之後）。
- 結果卡會把選項本身的效果和延遲後果、突發事件的衝擊分開顯示。
- `npm test` 會檢查「只衝民調」的玩法比「兼顧各數值」連任率低、危機多。

## 角色與事件的連動

- 政黨與出身會設定旗標（`party-blue`、`bg-legislator` 等），事件用 `conditions` 決定是否出現。
- 選項池事件（`drawOptions`）每次從符合 `appearsIf` 的選項中隨機抽出幾個，例如只有素人與小黨會抽到「不分藍綠」。
- 現任優勢不寫成固定加分，而是由 `perk` 選項產生（剪綵、市政廣告、加碼福利等），並有選民疲乏遞減。
