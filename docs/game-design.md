## 1. 目標與設計原則

**核心問題**：讓玩家反思「這真的是我們想要候選人做的事嗎？如果候選人做了這個選擇，我們應該支持他嗎？」

1. **樂趣與反思優先，不是吻合史實**。中選會數據只當參考，讓難度方向合理；不同角色的勝率本來就可以不同（小黨、無黨籍挑戰者本來就很難贏）。
2. **選舉誘因與公共利益的落差要被玩出來**：很多選項能換選票但傷原則、傷財政或動用公家資源；結局再讓玩家從選民角度回頭檢視。
3. **不能有單一必勝公式**：「只衝民調」不能是最佳解；每個數值都要能影響選票、解鎖或封鎖選項，或在過低時觸發負面事件。
4. **政治中立與虛構化**：城市、人物、政黨一律虛構；政黨只描述結構特性（組織、資源、形象），不評價政策立場，每個政黨都同時有優勢與包袱。事件與傳奇對手可以**影射**真實人物與事件，但不直接點名；刻意避開當屆（2026）選舉的參選人。
5. **可解釋**：勝選模型的權重公開在結局頁「為什麼是這個結果」，並註明「非真實得票預測」。
6. **事件從真實事件出發**：新事件先記下真實原型（`realCase`），再把城市、人名、數字模糊化，來源之後批次補上；不憑空寫虛構事件。

## 2. 遊戲流程

### 2.1 開局設定（全隨機）
1. 按「開始參選」後，**全部隨機**：城市 → 政黨 → 出身 → 3 個資質（1 個政治人格 + 2 個不同類別的能力資質）→ 1 個先天包袱 → 兩個階段的對手，全部由同一個 seed 決定。
   - 城市：天龍市、新龍市、航空城、媽媽市、古都市、港都市，等權重。各城市的選民結構與專屬事件見 3.3。
   - 政黨權重：藍 3、綠 3、白 2、黃 1、其他小黨 1、無黨籍 2。
   - 出身權重：現任 2、立委 3、議員 2、政務官 2、素人 2；第三勢力與無黨籍抽到現任市長的權重 × 0.4。每種政黨與出身的組合都抽得到。
   - 資質與包袱：符合出身或政黨的比較容易抽到（× 3），但每種都可能出現，包括純優勢或純弱勢的組合。
   - 資質品質與抽中權重見 3.4。
2. 播放「正在隨機你的人生…」動畫：每一格像拉霸一樣閃過候選值，再依序定格（約 3.5 秒，可跳過；系統設定減少動態時直接顯示結果）。全部定格後停在這一頁，玩家按「下一步」才進入人物介紹。
3. 角色卡：每張卡片上方有一行說明（卡片名稱＋這張卡對遊戲的影響），依序為：
   - **你的人設**：資質（依品質上色）與包袱標籤、顏色圖例、組合出的**人物介紹**。
   - **你的對手**：姓名或綽號、政黨・身分・實力、資質、第三人稱介紹；傳奇對手加「⭐ 傳奇對手」標章（見 8.5）。
   - **競選城市**：選民族群比例與最在意的議題。
   - **所屬政黨**、**出身背景**：說明、優勢與包袱、撥款與募款能力。
   - **預估難度**：用這組人設與對手，以隨機玩法模擬 300 次第一階段的當選率（≥55% 簡單、≥35% 普通、≥18% 困難、其餘地獄），附中選會史實參考。
4. 不能重抽，也不能選政黨。遊戲中隨時可以「宣布退選」（需二次確認），放棄這一局並回到開始畫面。

### 2.2 兩個階段，各 12 回合

| 階段 | 回合 | 階段代碼 | 說明 |
|---|---|---|---|
| 第一階段：競選 | 1 | `launch` | 參選事件：每種出身 3 個，隨機抽 1 個 |
| | 2 | `platform` | 主打政見（選項池，抽 3 個；目前每局都是同一個事件） |
| | 3–11 | `campaign` | 選戰事件，從 86 個中依條件與權重抽 9 個 |
| | 12 | `eve` | 選前之夜 |
| | — | — | **第一次投票**。落選則遊戲結束；當選則決定連任選舉的對手（捲土重來或新挑戰者） |
| 第二階段：任期與連任 | 1–8 | `term` | 任期事件（101 個池，另有 4 個劇情節點；到期的劇情節點優先出場） |
| | 9–11 | `incumbency` | 任期尾聲・現任限定（14 個池，另有 2 個劇情節點） |
| | 12 | `reelection` | 連任選戰（12 個池，含「對手踢爆」「上次的帳」等條件事件，另有 2 個劇情節點） |
| | — | — | **第二次投票** |

- **現任市長背景**：第一階段就是爭取連任（競選期有現任資源可用）；第二階段是不能再連任的第二任，最後一場改為**接班選舉**。
- **經費每 3 回合入帳一次**：第 1、4、7、10 回合（各階段）開始時。

### 2.3 每回合的處理順序（`engine.ts` 的 `choose`）
1. 套用選項效果（民調邊際遞減、團隊倍率、現任資源的選民疲乏）與經費收支。
2. 結算到期的延遲後果（包含突發事件的餘波）。
3. 媒體聲量退燒 3 點（最低退到 20）。
4. 每回合開銷：競選回合（`launch / platform / campaign / eve / incumbency / reelection`）依**競選規模**付人事、廣告、活動；任期回合（`term`）付服務處開銷 200 萬。
5. 個人貸款還款。
6. 檢查突發事件（每回合最多觸發 1 個）。
7. 若是第 12 回合：第一次投票（扣除選前動員經費），當選則換上連任選舉的對手；若是第 24 回合：遊戲結束。
8. 若到了入帳回合：入帳。
9. 抽下一個事件與選項。

## 3. 角色

詳細數值見附錄 A、B。

### 3.1 政黨

| 政黨 | 參考的結構特性 | 主要優勢 | 主要包袱 | 黨部撥款基數 |
|---|---|---|---|---|
| 藍黨 | 百年老黨：地方派系與基層組織深厚 | 政黨 +12、議會 +5、政商 +15 | 派系人情帳、老黨形象 | 800 萬 |
| 綠黨 | 大黨：組織動員強、與中央執政連動 | 政黨 +10、議會 +3、政商 +10 | 中央施政連坐、派系協調 | 750 萬 |
| 白黨 | 新興第三勢力：個人品牌、中間選民 | 民調 +3 | 政黨 −10、議會 −10 | 400 萬 |
| 黃黨 | 社運延伸的理念型小黨 | 原則 +8 | 政黨 −22、議會 −10、政商 −10 | 400 萬 |
| 其他小黨 | 議題單一、地方性 | 原則 +6 | 政黨 −21、議會 −12 | 250 萬 |
| 無黨籍 | 不受黨紀約束 | 原則 +5、民調 +3；小額捐款 ×2 | 政黨 −30、議會 −12；沒有黨部撥款 | 0 |

每個政黨有一個任期中的「包袱事件」（權重 3）：派系的人事帳單（藍）、中央施政連坐（綠）、議會只有兩席（白）、支持者的抗議（黃）、沒人認識你的黨（小黨）、兩大黨都來拉攏（無黨）。

### 3.2 出身

| 出身 | 起始調整 | 特色 |
|---|---|---|
| 現任市長 | 民調 +6、政績 +15、議會 +5、政商 +15 | 競選期就能動用現任資源；參選事件：四年成績單、局長被起訴了、黨中央想換人；第二階段為接班選舉 |
| 立委 | 民調 +3、政黨 +3、政商 +10 | 參選事件：要不要辭立委？、補選的接班人、沒有行政經驗；任期中「原選區補選」 |
| 市議員 | 民調 −3、議會 +5、政黨 +2、政商 +8 | 參選事件：全市知名度 12%、議長的人情、只做一任的承諾；任期中「老同事的質詢」 |
| 政務官 | 民調 +1、政績 +5、政商 +8 | 參選事件：前長官的光環、什麼時候辭職？、你簽過的那份公文；任期中「前長官的舊帳」 |
| 素人 | 民調 +1、原則 +5、議會 −5、政商 −10；小額捐款 ×2.5 | 參選事件：素人參選、本業怎麼辦、十年前的臉書；任期中「公文看不懂」 |

小額捐款倍率取政黨與出身中較高者（無黨籍素人 = 2.5）。

### 3.3 城市（選民結構）
每個城市有不同的選民族群、在意的議題與選舉生態（完整數值見附錄 B4）：

| 城市 | 主要選民 | 最在意的議題 | 選舉生態 |
|---|---|---|---|
| 天龍市 | 青年租屋族、白領通勤族 | 居住、交通 | 媒體影響 ×1.4，政黨組織 ×0.7；地方人情不管用 |
| 新龍市 | 跨區通勤族、重劃區新住民 | 交通、居住 | 政績與組織略重 |
| 航空城 | 產業工人、移入新住民 | 經濟產業、公共安全 | 政績 ×1.2 |
| 媽媽市 | 宮廟與地方派系、家長 | 地方人情、環境（空汙） | 政黨組織 ×1.4，媒體 ×0.8 |
| 古都市 | 長者、農漁民、文史社群 | 文化觀光、福利、地方 | 組織與政績略重 |
| 港都市 | 重工業與港口勞工、中小商家 | 經濟產業、公共安全 | 組織略重；開局財政較差 |

- **議題倍率**：事件有議題（`issue`，未設定時由標籤推斷），選項的民調效果會乘上城市對該議題的倍率；倍率偏離 1 達 0.3 以上時，結果文字補上城市的敘述（例如「天龍市的租屋族特別在意這件事」）。
- **選舉權重倍率**：勝選模型中各數值的權重乘上城市倍率。
- **開局調整**：例如天龍市市庫 +10、港都市市庫 −10。
- **城市變化**：部分一般事件依城市改寫結果（例如跑宮廟在媽媽市加分、在天龍市被說作秀；颱風後更新抽水站在新龍市、古都市特別有感）。
- **城市專屬事件**：每個城市 6–9 個（例如天龍市的社宅與北士科、媽媽市的遶境與空污旗、港都市的「又老又窮」與公墓遷葬），每局平均遇到約 1.6 個。

### 3.4 資質與先天包袱

每個角色有 3 個資質（1 個政治人格 + 2 個不同類別的能力資質：溝通與形象、政策與行政、組織與人際）與 1 個先天包袱。

- **29 個資質，分四級品質**，每一類都有負面與卓越：

  | 品質 | 顏色 | 抽中權重 | 抽中比例 | 例 |
  |---|---|---|---|---|
  | 負面 | 紅 | × 1 | 約 40% | 容易失言、決策遲緩、台語不輪轉、不食人間煙火 |
  | 普通 | 綠 | × 1.2 | 約 37% | 明星外型、網路梗王、財政專家、投機靈活 |
  | 優秀 | 藍 | × 0.8 | 約 18% | 辯論鬼才、行政老手、組織天才、清廉形象 |
  | 卓越 | 紫 | × 0.3 | 約 5% | 天生政治家、超級執行力、鐵票動員王、百折不撓 |

  約 16% 的角色至少有一個卓越資質。符合出身的資質抽中權重再 × 3。隨機動畫定格時與角色卡上都依品質上色。
- **品質對難度的影響**（隨機玩法、第一次投票）：有卓越資質 41%、一般 32%、兩個以上負面 23%。
- **資質的作用**：起始數值調整；能力（9 種 `skill`）擅長 +1 或不擅長 −1，影響選項結果（見 6.3）；部分事件有資質專屬選項與手寫的結果變化；人物介紹與後日談都會用到資質的敘述。
- **8 種先天包袱**：政治世家、財團家庭、地方宗族、明星家庭、社運網絡、家族利益衝突、歷史爭議、無資源孤軍。影響起始數值、開局經費、人物介紹的開場句，以及部分事件與後日談。

## 4. 數值系統

所有數值為 0–100，起始值：民調 50、媒體 40、市庫 60、政績 20、議會 50、團隊 50、政黨 50、政商 30、原則 70，再加上政黨與出身的調整。

| 數值 | 顯示 | 選票權重（每 10 點，logit） | 其他作用 | 太低／太高時的突發事件 |
|---|---|---|---|---|
| 民調支持 | ✓ | 0.45 | 小額捐款來源；超過 50 後加分遞減 | ≤45：市民上街抗議（任期） |
| 媒體聲量 | ✓ | 0.15 | 每回合退燒 3，最低 20 | ≤24：沒人記得你；≥70：過度曝光 |
| 市庫財政 | ✓ | 0.05 | 花錢的政策選項需要它；現任資源花的是它 | ≤22：財政警報；≥65：財政盈餘（正面） |
| 施政成果 | ✓ | 0.25 | 解鎖展示成果的選項 | ≤18：「市長到底做了什麼？」（任期尾聲）；≥45：國際城市獎（正面） |
| 議會關係 | ✓ | 0.05 | 政策選項的門檻 | ≤32：總預算遭凍結 |
| 團隊 | ✓ | 0 | 正向政績 × (0.5 + 團隊/100) | ≤42：局處長集體請辭 |
| 政黨支持 | ✓ | 0.20 | 黨部撥款倍率 | ≤20：黨內逼宮、黨部輔選放空 |
| 政商關係 | ✓ | 0 | 政治獻金來源 | ≥70：官商勾結疑雲 |
| 原則 | 隱藏 | 0 | 結局揭曉；高時解鎖公民團體背書 | ≤50：檢調搜索（任期）、競選醜聞（競選期）；≥80：公民團體肯定（正面） |

**數值調整規則**
- **民調邊際遞減**：正向民調效果 × (1 − (民調 − 50)/100)，民調 80 時剩七成。
- **團隊倍率**：正向施政成果 × (0.5 + 團隊/100)。
- **媒體退燒**：每回合 −3，退到 20 為止。
- **選民疲乏**：第 n 次動用現任資源，民調加分 × 0.65^(n−1)。

## 5. 競選經費

經費（萬元）與市庫財政是兩回事：前者是候選人自己的錢，後者是市府的錢。

### 5.1 收入（每 3 回合入帳）
畫面直接列出三項：
- **黨部撥款** = 政黨基數 × 政黨支持 / 50
- **政治獻金** = 政商關係 × 10
- **小額捐款** = (民調支持 − 35) × 12 × 小額捐款倍率（不為負）
- 其他：部分選項可以籌錢（募款餐會 +1,200、企業政治獻金 +2,500、建商的支票 +2,000 等，通常傷原則或拉高政商關係）。

開局經費範例：藍 1,780、綠 1,640、白 990、黃 770、小黨 710、無黨 850、無黨素人 720。

### 5.2 個人貸款
- 整局只能借一次，固定 3,000 萬，總利息 15%（共還 3,450 萬）。
- 從借款那回合起，到該階段結束平均分期，每回合自動扣款。
- 漏繳的期數之後會補扣；最後一回合一次扣清。
- 某期付不出來：民調 −4、媒體 +5（催收上新聞）。
- 階段結束仍未還清：「貸款違約」，民調 −10、原則 −5，債務註銷。

### 5.3 支出
- **競選規模**（玩家在每回合事件上方隨時切換，下一次開銷起生效）：

  | 規模 | 人事 | 廣告 | 活動 | 每回合 | 每回合效果 |
  |---|---|---|---|---|---|
  | 精簡 | 180 | 0 | 40 | 220 | 無 |
  | 標準 | 250 | 150 | 100 | 500 | 媒體 +1 |
  | 全面 | 400 | 450 | 350 | 1,200 | 媒體 +2、民調 +1 |

  黨部撥款 ≥ 700 的大黨從「標準」開始，其他人從「精簡」開始。付不起選定的規模會自動縮編（全面 → 標準 → 精簡）；連精簡都付不起就是**欠薪**：團隊 −4、民調 −2、媒體 −2，連續 2 回合欠薪會被幕僚爆料（旗標 `unpaid-staff`，後日談會寫到）。
- **預算面板**顯示目前規模的三項開銷、照這個規模還能撐幾回合、下次入帳在幾回合後與預估金額；撐不到下次入帳時以警示色提醒。
- **設計意圖**：第一階段大黨收入約 9,000 萬，標準規模 12 回合就要 6,000 萬，加上活動選項後，選前動員只剩約 1,500 萬（原本約 3,000 萬）；全面規模撐不了一半的回合，要撐住就得借貸。小黨收入約 3,500 萬，只撐得起精簡，想辦活動就得在人事和廣告之間取捨。
- **活動**：電視廣告 2,000、十萬人造勢 2,500、選前之夜大造勢 3,000、負面廣告 1,500、大咖藝人站台 1,200、專業選戰團隊 1,000 等。經費不足的選項顯示「🔒 經費不足」。
- **危機**：檢調搜索的律師費 1,500、競選醜聞退款 1,000、賄選案 1,000。
- **選前動員**：投票前，剩下的經費自動投入動員，最多 4,000 萬，每 1,000 萬加 0.15 logit。

### 5.4 現任優勢與經費
現任可以用**市府預算**辦「市政活動」（`perk` 選項，例如以市府名義辦活動、印施政成果手冊、選前追加里鄰建設）。這些選項花的是市庫財政，不花自己的競選經費；挑戰者要辦同樣的活動得自己出錢。

## 6. 事件系統

### 6.1 抽事件
- 每回合依 `TURN_PLAN` 的階段代碼，從該階段尚未出現過的事件中，挑出符合 `conditions` 的，再依 `weight` 抽一個。
- 若沒有符合條件的事件，退而從未出現過的事件中抽（測試會確保每種角色在第一階段至少有 9 個可抽的選戰事件）。

### 6.2 條件與旗標
- 政黨與出身在開局設定旗標：`party-blue / green / white / yellow / minor / independent`、`party-major`（藍綠）、`party-third`（白黃小黨）、`bg-incumbent / legislator / councilor / official / outsider`。
- 選項可設定旗標，讓之後的事件接續：
  - 承諾：`promise-housing-big`、`promise-cash`、`promise-mrt` 等，觸發任期中的追究事件（社宅進度報告、發錢的時候到了、試營運出包）。
  - 現任資源：`perk-ads`、`perk-li-chiefs`、`perk-rush`，觸發連任選戰的「對手踢爆」。
  - 突發事件：`investigated`、`scandal`、`fiscal-crisis`、`protested`、`vote-buying`，觸發後續事件或危機。
- 條件語法：`flags`（全部符合）、`anyFlags`（任一）、`notFlags`（排除）、`min` / `max`（數值門檻）。

### 6.3 選項
- **`requires`**：看得到但鎖住，顯示「🔒 需要 市庫財政 ≥ 30」。
- **`appearsIf`**：達到條件才會出現（例如政績 ≥ 50 才有「啟動任內建好的智慧抽水系統」、原則 ≥ 80 才有「公民團體聯署背書」）。
- **`funds`**：經費收支；負數且不足時鎖住。要花經費的選項，文字必須看得出錢花在哪裡（例如「砸錢投放」「租宣傳車」「紅包白包自己出」），事件檢查會擋下不符合的選項；附錄 E 列出所有花錢選項供人工確認。
- **`perk`**：動用現任資源，標示「🏛 動用現任資源（市府出錢）」，套用選民疲乏。
- **`delayed`**：數回合後才發生的後果（例如企業政治獻金 6 回合後爆出捐款人拿到標案）。
- **`legalRisk`**：標示違法風險（例如走路工：涉及賄選）。
- **`switchParty`**：改換政黨（目前用於黨內初選的退黨）。
- **`skill`**：選項用到的能力（辯論 debate、政策 policy、掃街 grassroots、媒體 media、行政 admin、組織 organize、協調 negotiate、利益交換 deal、正面衝突 confront）。資質對能力有擅長（+1）或不擅長（−1）；選這個選項時，等級加總為正就加上 `SKILL_EFFECTS` 的效果、為負就扣，並在結果文字後面補上資質的敘述。
- **`variants`**：依資質手寫的結果變化，第一個符合條件的會取代結果文字、加上額外效果，也可以換掉延遲後果；有變化時不再套用一般能力規則。目前用在電視辯論會、週末掃街、深度政策專訪。弱點的變化排在前面，所以同時有優點和弱點時，弱點優先（例如辯論鬼才又容易失言，攻擊對手會出包）。
- 資質專屬選項用 `appearsIf: { flags: ["trait-…"] }`，例如辯論鬼才才有「即興抓住對手的語病」、草根魅力才有「跟攤販一起叫賣」、政策學霸才有「帶著政策試算表上節目」。
- 被資質影響的選擇會記錄在歷史紀錄的 `traitsInvolved`，留給結局揭露（尚未實作）。
- **對手旗標**：對手會設定 `opp-legend-…`、`opp-trait-…`、`opp-party-…`、`opp-incumbent`、`opp-rematch`，讓對手事件只在遇到對應對手時出現（見 8.5）。
- **選項池**（`drawOptions`）：主打政見與選戰策略每次從符合 `appearsIf` 的選項中抽 3 個。
- **保證有路可走**：每個事件至少有一個「不花錢、沒門檻、不動用公家資源」的選項；選項池若抽到全是要錢或有門檻的，會換入一個這樣的選項。

### 6.4 事件數量（共 241 個）
參選 15（每種出身 3 個，開局隨機抽 1 個）、主打政見 1（14 個選項）、選戰 86、選前之夜 4、任期 105、現任限定 16、連任選戰 14。其中 25 個是對手事件、6 個是新寫的劇情節點（另有 2 個既有事件改為劇情節點）（16 個傳奇對手招牌事件、8 個對手出招、1 個捲土重來）。

來源狀態：`draft`（附來源與原文摘錄）125 個、`real`（改編自明確的真實事件，原型記在 `realCase`，來源待補）35 個、`placeholder`（虛構情境）81 個。**改編自真實事件的共 160 個（66%）**。

- **權重原則**：沒有出現條件的事件一律權重 1；只有限定城市、出身、政黨或對手的事件才加權（城市 2–2.5、對手出招 3、傳奇對手招牌 12），讓專屬事件在符合條件時容易遇到，又不會擠掉一般事件。測試會檢查沒有條件的選戰與任期事件出現率都低於 25%。

- **擴充原則**：新事件一律從真實事件出發，再把城市、人名、數字模糊化；先記下原型（`realCase`），來源之後批次補上。結局頁「真實事件原型」會依狀態標示「虛構情境」「改編自真實事件，來源整理中」「改編自真實事件，查核中」「改編自真實事件，已查核」。
- **城市專屬事件**：每個城市 6–9 個，以 `conditions: { flags: ["city-…"] }` 只在該城市出現。
- **耐玩度**：兩局隨機完整遊戲平均共同事件 4.4 / 24；每局平均遇到約 1.6 個城市專屬事件。`npm test` 會檢查共同事件 < 7。

### 6.5 劇情鏈與政治帳本（V0.4）

讓一個決定在之後的回合回來找你。劇情定義在 `web/src/content/arcs.json`，邏輯在 `web/src/game/story.ts`。

- **開啟**：選項的 `arcs` 欄位開啟劇情並記下事實（例如主打政見選「2 萬戶社宅」記下 `promised = 20000`）。
- **節點**：每條劇情有幾個節點，各自指定出場的階段與間隔；節點事件（`arc` 欄位）**只由排程安排，不會被隨機抽到**。例如「金主的請託」只會出現在收過建商錢的局。
- **排程**：每回合先看有沒有到期的劇情節點（依狀態急迫度、開啟先後排序），沒有才隨機抽事件。第二階段任期中（任期與任期尾聲）最多 3 個劇情回合（`ARC_QUOTA_STAGE2`）；連任選戰回合只演一個節點。
- **過期結算**：節點的階段結束還沒排上，就以快報（📒）結算並寫進帳本，不會無聲消失。第一次投票落選時不結算任期劇情，改由後日談寫「沒機會兌現的承諾」。
- **狀態**：進行中、已兌現、跳票、掩蓋中、已曝光。帳本依劇情種類換說法（人情債的「掩蓋中」是「私下回報」）。**掩蓋不等於兌現**：灌水的社宅在結局仍算沒做到。節點可以只在特定狀態出場（分支），例如私下回報才有「會議紀錄外流」、拒絕回報才有「建商改挺對手」。
- **旗標**：劇情狀態轉成 `arc-<id>`、`arc-<id>-<狀態>`、`arc-<id>-met`（有目標值的劇情達標），事件與選項沿用既有條件語法。
- **事實與文字**：事件文字可用 `{劇情.事實}` 代入數字，例如「承諾 {housing.promised} 戶，完工 {housing.built} 戶」。

| 劇情 | 開啟 | 節點 | 重點 |
|---|---|---|---|
| 社宅承諾 | 主打政見選「2 萬戶社宅」 | 社宅的地在哪裡（任期）→ 社宅進度報告（任期）→ 對手拿公報對帳（連任） | 記錄承諾、實際完工、對外宣稱三個數字；只有跟建商合建再加速發包才蓋得到 2 萬戶，誠實的路是下修目標 |
| 建商的人情 | 收下建商的支票、向金主承諾「選後照顧」 | 金主的請託（任期）→ 會議紀錄外流（私下回報時）或建商改挺對手（拒絕時） | 社宅找建商合建時，也會記進這本帳 |
| 地方派系的人情 | 派系大老的午宴、議長的人情、補選的接班人、黨內初選談條件、跑遍宮廟紅白帖 | 大老的人事名單（任期）→ 派系要挺誰？（連任） | 派系的選項依你怎麼處理人情而不同；已有派系劇情時，藍黨的「派系的人事帳單」不再出現 |

**政治帳本**：遊戲畫面上方顯示「📒 政治帳本：待處理 N 件」，展開後每筆劇情有種類、狀態、進度（三個數字）、每一步的回合與內容。結局頁「政治帳本結算」列出最後狀態。

**幕僚長回報**（`feedback.ts`）：每回合在事件上方顯示一句幕僚長的話，其他折疊成「快報」。依優先度挑選：突發事件、劇情曝光、欠薪、劇情剛有變化、經費撐不到撥款、民調大跌、數值跨過門檻（議會、團隊、政黨、政商、媒體、市庫），最後是平常日的閒話。數值類的話只在剛跨過門檻時說，之後隔幾回合才提一次；同一原因有多個版本，依 seed 決定。挑戰者在第一階段被稱為「老闆」，當選後改稱「市長」。測試確保連續兩回合同一句 < 12%。

**後日談**：多一段「帳本怎麼收場」，挑最值得寫的那條劇情（曝光 > 掩蓋 > 跳票 > 兌現），並可能成為大標（例如「把規劃中算成完工的市長」「容積換獻金被起訴的市長」）。

模擬 3,000 局（隨機玩法）：約 42% 的局至少開啟一條劇情（當選局 46%）；開啟率社宅 13%、建商 21%、派系 15%；第二階段劇情回合最多 3 個；每局因過期而以快報結算的節點約 0.1 個。

## 7. 突發事件（自動觸發，不是選項）

共 16 個，詳見附錄 C。

- **觸發**：每回合結束檢查，依 `priority`（數字小者優先）找第一個符合條件、階段，且可以發生的事件；每回合最多 1 個。

## 8. 選舉模型

```
logit = 基準 − 對手強度 + 選前動員 + Σ 權重[數值] × 城市倍率 × (數值 − 50) / 10
勝選機率 = sigmoid(logit)
實際結果 = sigmoid(logit + 擾動) ≥ 0.5，擾動為均勻分布 ±1.0（由 seed 決定，可重現）
```

- **基準**：第一次投票 `VOTE_BIAS = -0.32`；連任／接班選舉 `REELECTION_BIAS = 0.5`（加入對手系統與劇情鏈後重新校準：平均對手是中性的，劇情節點佔用的任期回合不讓連任率下降）。
- **對手強度**：依對手資質品質與身分計算，見 8.5。
- **城市倍率**：權重再乘上城市的選舉權重倍率（見 3.3）。基準與倍率都對所有角色一視同仁，不依政黨或出身加減分；難度差異來自起始數值、資質、經費、對手與事件。
- **選前動員**：min(剩餘經費, 4,000) / 1,000 × 0.15。
- **權重**見第 4 節：民調 0.45、政績 0.25、政黨 0.20、媒體 0.15、議會 0.05、市庫 0.05，其他為 0。
- **挑戰者的施政成果**：起始 20，在第一次投票會是扣分；結局頁說明為「你還沒執政過，選民拿對手的政績和你比較」。

## 8.5 對手

每一局有兩個對手：第一階段的對手，以及連任選舉時的挑戰者。兩者在開局時就由同一個 seed 抽好，角色卡上會介紹第一階段的對手。

- **傳奇對手**（約 20%）：16 位，以台灣歷史知名政治人物為原型，遊戲裡只用綽號影射，不點名。政黨不會和玩家相同。每位有手動指定的 3 個資質和一個**招牌事件**（例如庶民旋風的造勢旋風、世家公子「一直玩」的廣告、刑警市長的「我會努力」）。名單見附錄 B5。
- **隨機對手**：虛構姓名（常見姓氏加兩個字的名字），用和玩家相同的方式抽 3 個資質（同樣分紅綠藍紫品質）與 1 個包袱。大黨玩家的對手 85% 是另一個大黨、15% 是白黨；小黨與無黨籍玩家面對兩大黨之一。玩家是挑戰者時，對手有 30% 是尋求連任的現任市長。
- **對手強度**（從玩家勝選的 logit 扣除）：每個資質負面 −0.12、普通 0、優秀 +0.1、卓越 +0.2；現任市長 +0.15；捲土重來 +0.05。角色卡顯示「實力較弱／普通／強／很強」。為了讓平均對手是中性的，`VOTE_BIAS` 調成 −0.32、`REELECTION_BIAS` 調成 0.27。
- **對手出招**：對手的資質會觸發「對手出招」事件（辯論高手、造勢拚場、被做成迷因、金主被挖角、天價政見、對手失言、清廉牌、政績對照表）。對手的負面資質會變成你的機會，例如對手失言時，要不要趁勢猛打。
- **捲土重來**：第一次投票的模型勝率 ≤ 60%（贏得不多）時，同一位對手四年後回來，連任選舉多一個「上次的帳」事件；贏很多就換新的挑戰者。
- **呈現**：角色卡「你的對手」、遊戲畫面上方、第一次開票結果（含下一場的對手）、結局大圖與「為什麼是這個結果」的對手扣分。後日談不寫對手。

模擬 3,000 局：傳奇對手 18.7%；傳奇局有 83% 會遇到招牌事件；73% 的局會遇到對手出招；當選後約一半是對手捲土重來。第一次投票的當選率依對手強度：弱 42%、中 35%、強 27%。

## 9. 結局與反思

### 9.1 結局判定（有限種類，方便日後產生分享圖卡）

| 情境 | 結局 |
|---|---|
| 第一次投票落選，模型勝率 ≥ 40% | 差一點 |
| 第一次投票落選，勝率 < 40% | 落選 |
| 接班選舉勝／敗 | 交棒成功／江山易主 |
| 連任成功：政績 ≥ 55 且民調 ≥ 55 | 罕見的雙贏 |
| 連任成功：政黨 ≥ 60 且民調 < 55 | 組織的勝利 |
| 連任成功：其他 | 剪綵之王 |
| 連任失敗：政績 ≥ 50 | 被遺忘的建設者 |
| 連任失敗：市庫 ≤ 25 | 金庫見底 |
| 連任失敗：其他 | 一任市長 |

### 9.2 結局頁區塊（依序）
1. **開票結果大圖**：當選（連任成功、接班成功）是紅底金色彩帶加煙火；落選（連任失敗）是灰底、雨和倒下的旗子。大字顯示結果，上方是城市・政黨・出身，下方是對手與模型估計的勝選機率。
2. **後日談**：一句話大標（這個人的下場）＋ 6–7 段故事，下面是結局標語與**政治人格**（最常守護與最常犧牲的數值）。接著是「再來一局」按鈕，事件分析放在下方。
3. **換你當選民**：挑出最多 3 個「為了選票犧牲原則或動用公家資源」的選擇，加上 1 個「為了原則放棄民調」的選擇；兩者都沒有時，改問「你最受歡迎的一招」。玩家逐題回答「我會支持／我不會支持」，答完顯示總結與可複製的分享句，例如「我用來拿選票的 3 招裡，有 2 招，我自己當選民時不會支持」。
4. **兩張成績單**：經費收支、所有數值（含原則）、發生過的突發事件、留給下一任的帳單（任期結束時還沒爆的延遲後果）。
5. **為什麼是這個結果**：勝選機率、對手扣分、選前動員、各數值的貢獻與說明。
6. **你的現任優勢**（有機會動用時才顯示）：動用次數、換到的民調、花掉的市庫。
7. **現實中呢**：中選會數據（縣市長以上現任連任率 73%；落選時顯示該政黨非現任候選人的當選率）。
8. **真實事件原型**：本局遇到的每個事件的原型說明與來源連結。

### 9.3 後日談（`web/src/game/epilogue.ts`）

依這一局留下的痕跡組出結局後的故事。每一段從該段的片段清單中挑第一個符合條件的；多數片段有 2–3 個版本，依這一局的 seed 挑選（同一局重整不變）。

| 段落 | 依據 | 例 |
|---|---|---|
| 生涯 | 輸贏、哪一場選舉、是否中途出征（`ran-higher`） | 連任八年、只做一任、差一點、中途出征 |
| 關鍵抉擇 | 「換你當選民」挑出的選擇：拿原則換選票／為原則放棄選票／最受歡迎的一招 | 「違章宮廟」那一回，你選擇了「依法拆除」…… |
| 錢 | 貸款違約（`loan-defaulted`）、存款歸零、剩很多錢、市庫見底、留給下一任的帳 | 傾家蕩產、把積蓄押上選舉 |
| 良心 | 醜聞突發事件、違法風險選項次數、隱藏的原則值、特定選擇（`used-tragedy`、`fake-poll`、`thesis-fight`） | 被起訴、昧著良心、輸了選舉沒輸掉自己 |
| 人脈與個性 | 團隊、換黨、政黨、政商、媒體、議會、出訪對岸（`cross-strait-visit`）；都不特別時改用資質專屬句（29 種資質） | 進建設公司當顧問、政壇變色龍 |
| 家庭 | 先天包袱（8 種），再看任期長短 | 家族一起崩塌、把家留在市府之外 |
| 城市 | 6 座城市各有「做過市長／沒做過市長」兩組 | 天龍市的房價、媽媽市的宮廟主委 |

大標從各段的候選大標中取優先順序最高的；都沒有時用「參選過市長的人」等通用句。新增會留下強烈印記的事件時，記得在對應段落補上依旗標觸發的片段。

模擬 2,000 局：每一局的後日談都不同；固定段落最常出現的約 16%；大標最常出現的約 9%。

## 10. 內容來源與查核

- **中選會**：歷屆直轄市長、縣市長得票資料（1994–2022），推導現任連任率與各政黨挑戰者勝率（`web/src/content/history.json`）；直轄市長選舉公報 32 份（2010 年後可抽文字，2006 年以前為掃描檔）。
  - **公報全文含候選人地址與電話，只留在本機**（`.gitignore`），已從 git 歷史中移除；需要時用 `scripts/fetch_bulletins.py` 依 `manifest.json` 重抓。
- **政府文件**：臺中市研考會〈近三年監察院糾正案、調查報告案之說明與檢討〉（2022），作為 8 個任期事件的原型；監察院新聞稿。
- **新聞**：公視、中央社為主，另有報導者、聯合新聞網鳴人堂；共 118 筆新聞引文，都是報導標題或標題中的一段，由腳本抓取原網頁逐字比對（只保存引文與網址，不保存全文）。批次紀錄見 data-sources-review.md 第二到五批。
- **事件來源狀態**：`placeholder`（虛構情境）、`real`（改編自真實事件，原型記在 `realCase`，來源待補）→ `draft`（附來源與原文摘錄）→ `verified`（人工查核，需記錄查核者與日期）。上線前所有事件必須是 `verified`，`validateEvents(events, { release: true })` 會擋下未查核事件。
- **引文比對**：`scripts/check_quotes.py` 自動比對公報與政府文件的引文（本機需有公報全文）；目前 29 筆全部吻合。新聞引文在加入時以腳本逐字比對，仍需人工查核才能改為 `verified`。
- **來源待補**：29 個 `real` 事件（10 個開場事件、16 個傳奇對手招牌事件與其他 3 個）有原型但還沒附來源。
- 資料來源的審閱紀錄見 [data-sources-review.md](data-sources-review.md)。

## 12. 已知問題與待討論

**內容**
1. 241 個事件中，125 個附來源（`draft`），35 個有真實原型但來源待補（`real`），81 個是虛構情境（`placeholder`，其中 9 個是對手出招與捲土重來這類機制事件）。上線正式版前，所有事件都要人工查核為 `verified`。
2. 敏感內容需要人工審閱：「樁腳的走路工」（賄選）、「家人被起底」、選前之夜的槍聲、捷運隨機攻擊、各政黨的包袱描述與顏色對應現實政黨、16 位傳奇對手的影射寫法。
3. 有旗標被設定但沒有任何事件或後日談接續：主打政見的 7 個承諾（`promise-air`、`promise-flood`、`promise-housing-modest`、`promise-renewal`、`promise-senior`、`promise-tourism`、`promise-one-term`）、`party-deal`、`perk-no-leave`。
4. 「主打政見」每局都是同一個事件（選項隨機），可以再做 2 個不同情境，讓它也變成三選一。
5. 2006 年以前的公報是掃描檔，需要 OCR 才能取材。

**平衡**
6. 小黨與無黨籍挑戰者目前約 8–9%，略低於設計目標的 10%。
7. 隨機玩法的首任市長連任率約 59%，低於史實的 73%（設計上不追求吻合，但是否太難可以討論）。
8. 「團隊」和「媒體聲量」被選項影響的次數較少，媒體幾乎只會上升（靠退燒下降）。
9. 挑戰者第一次投票時，施政成果固定扣分（起始 20），目前只用說明文字處理。

**玩法與呈現**
10. 城市議題的補充敘述每個議題只有一句，同一局遇到多個同議題事件時會重複出現。
11. 還沒有分享圖卡。
12. 被資質影響的選擇（`traitsInvolved`）還沒有在結局揭露。
13. 個人貸款只有一種金額，是否要提供不同額度或利率？
14. 第二階段的「現任限定」只在任期尾聲 3 回合，任期中段沒有選舉壓力的體感。
15. 還沒有匿名統計（例如「多少玩家不會支持自己用過的招」），需要後端。
16. 存檔只在玩家自己的瀏覽器，換裝置不會帶過去。

## 13. 技術架構

```
web/                          Next.js 16 靜態網站（output: export），無後端
  next.config.ts              basePath 由 PAGES_BASE_PATH 決定（GitHub Pages 為 /ElectionLife）
  src/game/types.ts           型別：數值、事件、選項、政黨、出身、資質、包袱、城市、對手、傳奇對手、貸款、競選規模
  src/game/model.ts           所有平衡常數：選舉權重、競選規模、對手強度、貸款
  src/game/engine.ts          回合引擎（純函式，同一個 seed 可重現）
  src/game/profile.ts         人設與對手抽取、虛構姓名、人物介紹與對手介紹
  src/game/endings.ts         結局、政治人格、換你當選民、現任優勢統計
  src/game/epilogue.ts        後日談
  src/game/story.ts           劇情鏈：開啟、推進、排程、過期結算、帳本文字
  src/game/feedback.ts        幕僚長回報
  src/game/difficulty.ts      角色卡的難度估算
  src/game/validate.ts        事件庫檢查
  src/game/engine.test.ts     72 項測試（含平衡）
  src/content/                events / arcs / crises / parties / backgrounds / traits / burdens / cities / legends / history（JSON）
  src/app/Game.tsx            遊戲與結局畫面
  src/app/RollingScreen.tsx   「正在隨機你的人生」動畫
  src/app/ResultBanner.tsx    結局頁的開票結果大圖
scripts/                      中選會抓取、彙總、引文檢查、附錄產生
data/                         原始資料與彙總（公報 PDF 與全文不進 git）
docs/                         設定文件、附錄、資料來源審閱
.github/workflows/pages.yml   推到 main 時測試、建置並部署到 GitHub Pages
```

常用指令：`npm run dev`、`npm test`、`npm run build`（在 `web/`）；`python -I scripts/check_quotes.py`、`python -I scripts/export_design_tables.py`（在專案根目錄）。

**部署**：推到 `main` 會觸發 GitHub Actions，先跑測試，通過後以 `PAGES_BASE_PATH=/ElectionLife` 建置並發佈到 GitHub Pages；測試沒過就不會部署。日後換網域或改用其他服務時，拿掉 `PAGES_BASE_PATH` 即回到根路徑。

存檔放在瀏覽器 localStorage（`election-life:mayor:v1`），版本號 `STATE_VERSION = 15`，版本不符時舊存檔作廢，開始畫面會提示「遊戲更新了，請開始新的一局」。

V0.3 改版規劃的決議紀錄見 [v0.3-decisions.md](v0.3-decisions.md)。
